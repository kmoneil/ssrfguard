# The address table

`DEFAULT_DENIED` is what decides whether an address may be connected to. It is **60 rows
generated from the IANA special-purpose address registries**, not a hand-written list of private
ranges, and the difference shows up in four places.

```python
>>> from ssrfguard import DEFAULT_DENIED, REGISTRY_SNAPSHOT
>>> DEFAULT_DENIED
<AddressTable 60 blocks, registry 2026-08-22>
>>> REGISTRY_SNAPSHOT
'2026-08-22'
```

[`examples/09_address_table.py`](../examples/09_address_table.py) runs everything on this page.

## A row

```python
Block(
    network=IPv4Network("169.254.0.0/16"),
    name="Link Local",
    rfc="RFC3927",
    reach=Reach.DENIED,
    note="",
)
```

The name and the RFC are not decoration. They are what the refusal message quotes, and a refusal
a user cannot act on gets configured around. `note` carries why an entry departs from the
registries, and is empty when it does not.

## Asking it a question

```python
>>> verdict = DEFAULT_DENIED.classify("169.254.169.254")
>>> verdict.blocked
True
>>> verdict.reason
'169.254.169.254/32 is Cloud metadata (AWS, GCP, Azure IMDS) (RFC3927)'
>>> verdict.block.rfc
'RFC3927'
```

`classify` returns a `Verdict` carrying `address`, `blocked`, the deciding `block`, and the
`chain` of wrappers it walked to get there. `raise_if_blocked()` turns it into a
`BlockedAddressError`. `match(ip)` returns the deciding `Block` without forming a verdict.

For the policy-level question, which also consults `allowed_networks`, use
`Policy.check_address` or `Policy.permits_address`.

## Reach: three answers, not two

```python
class Reach(enum.Enum):
    DENIED = "denied"          # refuse any address in this block
    PERMITTED = "permitted"    # allow, overriding an enclosing denied block
    TRANSLATED = "translated"  # decode the address inside and ask again about that
```

`PERMITTED` exists because IANA marks a handful of special-purpose blocks globally reachable:
public anycast services, AS112, AMT. **Refusing those would be a denial with no security benefit
behind it**, and a guard with false positives gets removed, and a removed control protects
nothing.

## Longest prefix wins

The table resolves like a routing table, so a specific row can permit something inside a denied
one:

```
DENY  192.0.0.1     decided by 192.0.0.0/24 (IETF Protocol Assignments, denied)
allow 192.0.0.9     decided by 192.0.0.9/32 (Port Control Protocol Anycast, permitted)
allow 192.0.0.10    decided by 192.0.0.10/32 (Traversal Using Relays around NAT Anycast, permitted)
allow 192.0.0.171   decided by 192.0.0.171/32 (NAT64/DNS64 Discovery, permitted)
```

## Wrappers are decoded, not answered about

This is the part a hand-written list gets wrong. `::ffff:169.254.169.254` is not "an IPv6 address
that is probably fine". It is the metadata endpoint with four extra colons.

```
DENY  ::ffff:127.0.0.1
      decoded through IPv4-mapped Address ::ffff:0.0.0.0/96 -> 127.0.0.1
      IPv4-mapped Address ::ffff:0.0.0.0/96 carries 127.0.0.1, and 127.0.0.0/8 is Loopback (RFC1122)

DENY  64:ff9b::a9fe:a9fe
      decoded through IPv4-IPv6 Translation 64:ff9b::/96 -> 169.254.169.254
      IPv4-IPv6 Translation 64:ff9b::/96 carries 169.254.169.254, and 169.254.169.254/32 is
      Cloud metadata (AWS, GCP, Azure IMDS) (RFC3927)
```

A string comparison against `"169.254."` catches none of these. A parsed address and a table that
decodes catches all of them, which is why the check is structural rather than a pattern. The
verdict carries the chain it walked, so a refusal can say what it decoded.

This is also the reason
[`allowed_networks` refuses a translation prefix](policy.md#reaching-your-own-internal-services):
`allowed_networks` is consulted before the table gets to decode, so an entry inside a wrapper
would permit everything embedded in it.

## Where the rows come from

Generated by `python scripts/refresh_registry.py`, which fetches the IANA IPv4 and IPv6
special-purpose address registries and rewrites `src/ssrfguard/_registry.py`.

**Do not hand-edit that file.** A registry change is a change to what this package refuses and is
reviewed as one: run the script, read the diff, and say in the changelog what moved. The `egress`
lane regenerates from IANA in CI and compares, so a registry that has moved on shows up as a
failing build rather than as a quiet divergence.

A handful of entries depart from the registries, each carrying a `note` saying why.
`169.254.169.254/32` is the obvious one: IANA has nothing to say about it, and it is the single
address every SSRF advisory names.

## Building your own

### Add rows to the shipped table

```python
import ipaddress
from ssrfguard import DEFAULT_DENIED, AddressTable, Block, Policy, Reach

ours = Block(
    network=ipaddress.ip_network("192.30.252.0/22"),
    name="Our own build fleet",
    rfc="internal policy",
    reach=Reach.DENIED,
)
policy = Policy(denied_networks=AddressTable(blocks=(*DEFAULT_DENIED.blocks, ours)))
```

A duplicate network raises `ValueError` at construction, so you cannot accidentally shadow a
shipped row with a second copy of it. To _change_ what a shipped row says, filter it out and add
your replacement.

### An empty table

```python
Policy(denied_networks=AddressTable(blocks=()))
```

Denies nothing. Every other check in the policy still runs: scheme, port, credentials, control
characters, encoded hosts, length. Prefer this to a wide `allowed_networks` entry when the intent
is "no address filtering", and the NAT64 refusal says so in as many words.

## Where the table departs from IANA, and why

Ten rows carry a `note` that is not a metadata endpoint, and every one of them is a place where following the registry literally
would have produced a wrong answer. Read these before deciding the table is just a copy of a web
page.

**Three deprecated blocks that IANA removed.** `::/96` (IPv4-compatible), `fec0::/10`
(site-local) and `2001:10::/28` (previously ORCHID) are gone from the registry, so a table built
from IANA alone permits them. The standard library reports `is_global` true for some of them.
They are denied here.

**Two multicast ranges IANA keeps in a different registry.** `224.0.0.0/4` and `ff00::/8` are not
in the special-purpose table at all, so a generated table would miss them. The IPv6 side is
worse: `ff02::1` is all-nodes, and the standard library reports it as globally reachable.

**`64:ff9b::/96` is marked globally reachable by IANA, which is correct about routing** and
useless as an answer. The prefix genuinely is public. What it carries is not, so it is decoded
anyway.

**`::ffff:0.0.0.0/96` is marked _not_ globally reachable, which read literally is a flat
refusal.** That would be a wrong deny: the mapped form of a perfectly ordinary public address is
a perfectly ordinary public address. It is decoded rather than refused.

**`2002::/16` and `2001::/32` answer N/A**, precisely because reachability depends on the
embedded address. Both are decoded. Teredo carries two IPv4 addresses, the server and the client,
and both are checked.

An address this package refuses that it should permit is as much a bug as the reverse. A guard
with false positives gets removed, and a removed control protects nothing, which is why half of
those notes exist to prevent a wrong _deny_ rather than a wrong allow.
